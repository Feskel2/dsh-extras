# topmost-notify: host-компонент нативного уведомления

Нативное окно-уведомление для DSH: безрамочная topmost-карточка поверх всех окон,
короткий звук одновременно с появлением карточки и авто-закрытие. Windows PowerShell 5.1 + WPF.

Два вида уведомления:

| Вид (`kind`) | Когда | Акцент карточки | Звук |
| --- | --- | --- | --- |
| `completed` | ход завершён | синий → фиолетовый (`#5B9DFF` → `#9B6BFF`) | `chime.wav` — восходящая кварта A5→E6, тёплый «динь» |
| `question` | чат ждёт ответа пользователя | янтарный → оранжевый (`#FFB454` → `#FF7A45`) | `chime-question.wav` — двойной восходящий сигнал E5→B5, «вопросительный» |

## Файлы

| Файл | Назначение |
| --- | --- |
| `notify.ps1` | Показывает окно, играет звук, закрывается сам. UTF-8 **с BOM** (иначе PS 5.1 читает кириллицу как ANSI) |
| `chime.wav` | Звук «выполнено»: 44.1 кГц, 16 бит, моно, 1.2 с, пик −4.1 dBFS |
| `chime-question.wav` | Звук «нужен ответ»: тот же формат, другой тембр и рисунок |
| `make-chime.mjs` | Детерминированный генератор обоих WAV (Node, без зависимостей и сети) |
| `test-notify.ps1` | Реальные замеры обоих видов + скриншоты в `../artifacts/` |

## Как запускать

Из host-плагина (контракт):

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <путь>\host\notify.ps1 -PayloadBase64 <base64>
```

Payload — JSON в UTF-8, закодированный в base64:

```json
{
  "title": "Нужен ответ",
  "body": "Агент ждёт ответа: подтвердите действие в чате",
  "durationMs": 1000,
  "sound": true,
  "kind": "question"
}
```

| Поле | Тип | Смысл |
| --- | --- | --- |
| `title` | string | заголовок карточки (по умолчанию «Задача выполнена», для `question` — «Нужен ответ») |
| `body` | string | 1–2 строки, лишнее обрезается многоточием |
| `durationMs` | number | сколько окно висит, 300…15000 (по умолчанию 1000); вне диапазона — зажимается |
| `sound` | `true` \| `false` \| `"путь\\к\\файлу.wav"` | звук: включён / выключен / **свой WAV** (абсолютный путь или относительно папки скрипта). Если файл не найден — предупреждение в stderr и стандартный звук этого вида |
| `kind` | `"completed"` \| `"question"` | вид: цвет акцента и стандартный звук (принимаются также `done`, `waiting`, `ask`) |

Ручной запуск без base64:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File host\notify.ps1 `
    -Title "Задача выполнена" -Body "Проверка окна" -DurationMs 1500
# -Kind question          — вопросительный вид (янтарный акцент + chime-question.wav)
# -SoundFile "D:\snd\my.wav" — свой звук
# -Silent                 — без звука
# -Diag                   — тайминги этапов в stderr
```

Коды выхода: `0` — окно показано и закрыто штатно; `1` — ошибка (текст в stderr,
например битый base64 или отсутствующий `chime.wav`; окно при этом не показывается).

## Что host уже умеет для настроек плагина

UI настроек (тумблер, поля) живёт в `client.js`/`index.mjs`, а host принимает уже готовые значения.
Чтобы настройки заработали, `index.mjs` должен прокинуть их в payload:

| Настройка в UI | Поле payload | Ограничения |
| --- | --- | --- |
| время показа окна | `durationMs` | 300…15000 мс, host зажимает сам |
| свой звук «задача выполнена» | `sound` = путь к WAV при `kind: "completed"` | WAV PCM 16 бит; при отсутствии файла — стандартный звук |
| свой звук «нужен ответ» | `sound` = путь к WAV при `kind: "question"` | то же |
| выключить звук | `sound: false` | — |
| вид уведомления | `kind` | `completed` \| `question` |

| Метрика | completed | question |
| --- | --- | --- |

| управляемая часть «старт скрипта → видимое окно» | 1247 мс | 813 мс |
| звук стартует | +232 мс после появления окна | +153 мс |
| цвет акцент-полоски (по пикселю скриншота) | `#7B84FF` (холодный) | `#FF974C` (янтарный) |
| topmost | `WS_EX_TOPMOST` = да, `WindowFromPoint(центр)` = наше окно | то же |

## Известные ограничения

1. **Цель ≤ 800 мс при запуске процесса на каждый показ недостижима на этой машине**
   (согласовано: принимаем ~2 с). Только запуск `powershell.exe` 5.1 занимает ~0.66–0.73 с
   (для сравнения `cmd /c exit` — ~20 мс), холодная инициализация WPF — ещё ~0.8–1.2 с.
   Что уже выжато: ручной разбор плоского JSON вместо `ConvertFrom-Json` (−230 мс, тот тянет
   JavaScriptSerializer), построение UI кодом вместо `XamlReader.Parse` (−500…700 мс).
   Вариант ускорения до ~0.2–0.3 с — тёплый процесс-демон, но от него отказались:
   не хотим держать фоновый процесс в системе пользователя.
2. **Exclusive fullscreen** (игры, некоторые видеоплееры) может перекрывать topmost-окно —
   это ограничение Windows. Обычный borderless-fullscreen и другие приложения — ок.
3. Окно показывается с `ShowActivated=false`, поэтому не забирает фокус. `WS_EX_NOACTIVATE`
   сознательно не выставляется (окно остаётся кликабельным); карточка живёт `durationMs` и закрывается сама.
4. Нужен STA-поток: `powershell.exe` 5.1 по умолчанию STA. При запуске из PowerShell 7 добавляйте `-STA`.
5. Звук стартует в `Loaded`, то есть одновременно с появлением карточки (+150…230 мс на этой машине).
   Если WPF-часть упала до показа окна, звук всё равно проигрывается (фолбэк после `try/catch`).
   Хвост звука дожидается до 350 мс после закрытия окна, чтобы «динь» не обрывался.
6. Позиция фиксированная (правый верхний угол рабочей области, отступ 24 px). Несколько
   уведомлений подряд перекрывают друг друга; окно не ставится в очередь.
7. DPI: координаты считаются в DIP через `SystemParameters.WorkArea`, поэтому при масштабе
   экрана ≠ 100 % карточка остаётся в правом верхнем углу.
8. Заголовок окна `DSH topmost-notify` используется тестом для поиска hwnd — не переименовывать
   без правки `test-notify.ps1`.
9. Свой WAV из настроек: если файл удалён/переименован, host пишет предупреждение в stderr
   и играет стандартный звук нужного вида (уведомление не ломается).

## Перегенерировать звуки и прогнать тест

```powershell
node host\make-chime.mjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File host\test-notify.ps1
```

`test-notify.ps1` для каждого вида находит окно по PID, меряет латентность и синхронность звука,
проверяет topmost, сохранность фокуса, цвет акцента по пикселю, WAV и авто-закрытие,
снимает скриншот всего экрана и кроп вокруг окна.
Параметры: `-Kind completed|question|both`, `-DurationMs`, `-LatencyTargetMs`, `-SoundSyncToleranceMs`, `-Silent`.
