# Настройка Yandex SpeechKit: от пустого аккаунта до работающего голоса

Этот гайд проводит через всю облачную часть Яндекса для двух голосовых плагинов DSH:

| Плагин | Что делает | Сервис SpeechKit |
|---|---|---|
| [`dsh-voice-reply`](../dsh-voice-reply/README.ru.md) | Озвучивает краткое содержание каждого готового ответа (TTS) | Синтез речи |
| [`dsh-speech-to-text-yandex`](../dsh-speech-to-text-yandex/README.ru.md) | Добавляет провайдер `yandex-speechkit` в Voice input (STT) | Распознавание речи |

Плагины независимы, но настройка почти одинаковая: один облачный аккаунт, один платёжный аккаунт, один каталог, один сервисный аккаунт с одной или двумя ролями и один или два API-ключа. **Ключ для TTS и ключ для STT — разные ключи**: у них разные области действия, и один не заменяет другой.

**Короткий путь (если вы уже знаете Yandex Cloud):** создать каталог → создать сервисный аккаунт → выдать на каталог `ai.speechkit-tts.user` и/или `ai.speechkit-stt.user` → создать API-ключ с областью действия `yc.ai.speechkitTts.execute` и/или `yc.ai.speechkitStt.execute` → вписать ключ в `plugin-config.json` рядом с установленным плагином (или в переменную окружения) → перезапустить `dsh web` → проверить результат на странице настроек плагина. Дальше документ объясняет каждый шаг, точные имена и что делать, если не заработало.

> SpeechKit — платный сервис. Бесплатно по умолчанию ничего нет: каждый не закэшированный синтез и каждый запрос распознавания тарифицируется Yandex Cloud. Перед тем как оставить это работать, прочитайте [раздел «Стоимость»](#7-стоимость).

Гайд сверен с документацией Yandex Cloud в ноябре 2026 года. Сейчас Яндекс документирует SpeechKit в составе Yandex AI Studio, поэтому часть ссылок `yandex.cloud/.../speechkit/...` перенаправляет на `aistudio.yandex.ru`; и то и другое — официальная документация.

## 1. Что понадобится

| Компонент | Зачем нужен |
|---|---|
| **Аккаунт Yandex Cloud** (Яндекс ID) | Владеет облаком, каталогом и ключами; работа идёт в [консоли управления](https://console.yandex.cloud) |
| **Активный платёжный аккаунт** | SpeechKit — платный сервис; без активного биллинга вызвать его нельзя |
| **Каталог** (folder) | Контейнер, в котором создаётся сервисный аккаунт; роли назначаются на каталог, а его идентификатор — это `folderId` |
| **Сервисный аккаунт** | Технический аккаунт (не для человека) — владелец API-ключа; плагин авторизуется от его имени |
| **Роль** на каталог | Даёт сервисному аккаунту право вызывать синтез или распознавание |
| **API-ключ с областью действия** (или IAM-токен) | Сам секрет; область действия ограничивает, что можно вызывать этим конкретным ключом |

Плюс со стороны DSH:

- DSH `>=0.2.2-rc.1 <0.3.0-0`, профиль `web`, Node.js `>=24.9.0`;
- исходящий HTTPS к `tts.api.cloud.yandex.net` и/или `stt.api.cloud.yandex.net`;
- браузер, который умеет проигрывать звук (для TTS), и микрофон (для STT).

### Два плагина и что у них общего

| | `dsh-voice-reply` (TTS) | `dsh-speech-to-text-yandex` (STT) |
|---|---|---|
| Роль на каталог | `ai.speechkit-tts.user` | `ai.speechkit-stt.user` |
| Область действия API-ключа | `yc.ai.speechkitTts.execute` | `yc.ai.speechkitStt.execute` |
| Endpoint | `https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize` | `https://stt.api.cloud.yandex.net/speech/v1/stt:recognize` |
| Источники доступа | переменные окружения, затем `plugin-config.json` | config в `cordis.patch.yml`, затем переменные окружения, затем `plugin-config.json`, затем значения по умолчанию |
| Установка | Tarball GitHub-релиза — см. [инструкцию](install.ru.md) | Tarball GitHub-релиза — см. [инструкцию](install.ru.md) |

Что у них общего:

- один и тот же облачный аккаунт, каталог и (при желании) один и тот же сервисный аккаунт;
- одинаковые два локальных способа доставки — переменные окружения и локальный `plugin-config.json`;
- одинаковые режимы авторизации — `Authorization: Api-Key <ключ>` либо `Authorization: Bearer <IAM-токен>` плюс идентификатор каталога;
- одинаковая модель безопасности — ключ остаётся в процессе хоста `dsh web`, не уходит в браузер и не пишется в журнал плагина;
- одинаковая тарификация — Yandex Cloud берёт деньги за каждый вызов, который не обслужен локальным кэшем.

Одного сервисного аккаунта с обеими ролями достаточно. Создайте **два API-ключа** (по одному на область действия), а не один ключ с двумя областями: если ключ утечёт, вы отзовёте только пострадавший сервис.

## 2. Создаём облачную часть

Нужен доступ к каталогу с правом создавать сервисные аккаунты и назначать роли (`iam.serviceAccounts.admin` или выше, либо владелец каталога). Если вы единственный пользователь свежего аккаунта, это право у вас уже есть.

### 2.1 Включаем биллинг

1. Откройте [Yandex Cloud Billing](https://center.yandex.cloud/billing/accounts).
2. Создайте платёжный аккаунт, если его нет, и привяжите способ оплаты.
3. Убедитесь, что аккаунт **активен** и нет блокировки за долг. У физических лиц новые аккаунты обычно сразу начинают работать в платном потреблении; пробный период и стартовый грант зависят от типа аккаунта, региона и даты — смотрите, что показывает ваша страница биллинга, а не исходите из наличия бесплатного периода.

Официальная страница: [Регистрация аккаунта в Yandex Cloud](https://yandex.cloud/ru/docs/billing/quickstart/).

**Проверка:** на странице биллинга аккаунт активен, облако не заблокировано за неоплату.

### 2.2 Создаём каталог

Каталог — это место, где живут сервисный аккаунт и его роли. Его идентификатор плагины называют `folderId`.

Консоль:

1. В [консоли](https://console.yandex.cloud) выберите своё облако в верхней панели.
2. Откройте страницу облака и нажмите **Создать каталог**.
3. Дайте понятное имя, например `dsh-speechkit`, и создайте каталог.
4. Откройте каталог и скопируйте его **идентификатор** (строка вида `b1g...`). Это не секрет, но он понадобится для режима IAM.

CLI (необязательно):

```powershell
yc resource-manager folder create --name dsh-speechkit
yc resource-manager folder list
yc config get folder-id
```

`yc config get folder-id` печатает каталог, выбранный в текущем профиле CLI; `yc resource-manager folder list` показывает все каталоги с идентификаторами.

Официальные страницы: [Создание каталога](https://yandex.cloud/ru/docs/resource-manager/operations/folder/create) и [Получение идентификатора каталога](https://yandex.cloud/ru/docs/resource-manager/operations/folder/get-id).

**Проверка:** идентификатор каталога записан где-то, но не в конфиге плагина.

### 2.3 Создаём сервисный аккаунт

Консоль:

1. Выберите каталог в верхней панели.
2. Перейдите в **Identity and Access Management** (быстрая ссылка — [console.yandex.cloud/link/iam](https://console.yandex.cloud/link/iam)).
3. Откройте **Сервисные аккаунты** и нажмите **Создать сервисный аккаунт**.
4. Назовите его, например `dsh-speechkit`. Имя — от 3 до 63 символов: строчные латинские буквы, цифры и дефисы, первый символ — буква, последний — не дефис.
5. Нажмите **Создать**. Аккаунт создаётся внутри выбранного каталога и позже не переносится.

CLI:

```powershell
yc iam service-account create --name dsh-speechkit
yc iam service-account get dsh-speechkit
```

Поле `id:` в выводе — идентификатор сервисного аккаунта; он понадобится для выдачи роли через CLI.

Официальная страница: [Создание сервисного аккаунта](https://yandex.cloud/ru/docs/iam/operations/sa/create).

### 2.4 Выдаём роли

Сервисному аккаунту нужно разрешение на **каталог** (роли на облако или организацию тоже наследуются каталогом, но выдача на каталог — самый предсказуемый вариант).

| Плагин | Роль |
|---|---|
| `dsh-voice-reply` | `ai.speechkit-tts.user` |
| `dsh-speech-to-text-yandex` | `ai.speechkit-stt.user` |

Если используете оба плагина, выдайте обе роли одному аккаунту.

Консоль:

1. Откройте страницу каталога.
2. Перейдите на вкладку **Права доступа**.
3. Нажмите **Настроить доступ**.
4. Откройте раздел **Сервисные аккаунты** и выберите `dsh-speechkit`.
5. Нажмите **Добавить роль**, найдите `ai.speechkit-tts.user` и/или `ai.speechkit-stt.user` и добавьте их.
6. Нажмите **Сохранить**.

CLI:

```powershell
yc resource-manager folder add-access-binding <folder-id> `
  --role ai.speechkit-tts.user `
  --service-account-id <service-account-id>

yc resource-manager folder add-access-binding <folder-id> `
  --role ai.speechkit-stt.user `
  --service-account-id <service-account-id>
```

Проверить выданное:

```powershell
yc resource-manager folder list-access-bindings <folder-id>
```

Официальные страницы: [Назначение роли сервисному аккаунту](https://yandex.cloud/ru/docs/iam/operations/sa/assign-role-for-sa) и [Управление доступом в SpeechKit](https://yandex.cloud/ru/docs/speechkit/security/).

**Распространение прав:** новые разрешения обычно применяются за секунды, но могут занять несколько минут. Единичный `401`/`403` сразу после выдачи роли — нормально; повторите через пару минут, прежде чем что-то менять.

**Проверка:** в списке прав каталога есть роль и сервисный аккаунт; либо `list-access-bindings` это печатает.

### 2.5 Создаём API-ключ

API-ключ — рекомендуемый доступ для настольной установки: он не истекает, если не задать срок, и не требует фонового обновления.

Консоль:

1. Перейдите в **Identity and Access Management → Сервисные аккаунты**.
2. Откройте `dsh-speechkit`.
3. В блоке **API-ключи** нажмите **Создать новый ключ** и выберите **Создать API-ключ**.
4. Добавьте описание, например `dsh-voice-reply TTS` или `dsh-speech-to-text STT`. Так ключи проще отличать друг от друга потом.
5. В поле **Область действия** выберите ровно одну область для этого ключа:
   - `yc.ai.speechkitTts.execute` — для `dsh-voice-reply`;
   - `yc.ai.speechkitStt.execute` — для `dsh-speech-to-text-yandex`.
6. При желании задайте **срок действия**. Ключ со сроком безопаснее, но о ротации придётся помнить.
7. Нажмите **Создать**.
8. **Сразу скопируйте секретный ключ.** Yandex Cloud показывает его только один раз, в диалоге создания; после закрытия диалога остаётся только замаскированное значение. Если ключ потерян, его нельзя восстановить — удалите его и создайте новый.

CLI:

```powershell
yc iam api-key create `
  --service-account-name dsh-speechkit `
  --description "dsh-voice-reply TTS" `
  --scopes yc.ai.speechkitTts.execute

yc iam api-key create `
  --service-account-name dsh-speechkit `
  --description "dsh-speech-to-text STT" `
  --scopes yc.ai.speechkitStt.execute
```

Каждая команда печатает YAML с полем `secret:` — сохраните его сразу.

Две детали, которые часто путают:

- **Пустая область действия — это не то же самое, что значение по умолчанию в CLI.** Если оставить поле области действия пустым в консоли, ключ ограничен только ролями сервисного аккаунта (шире). Если не указать `--scopes` в CLI, Яндекс назначит список областей по умолчанию, в который уже входят обе области SpeechKit. Для минимальных прав указывайте одну нужную область явно.
- **API-ключ — это не IAM-токен.** Не вставляйте его в `YANDEX_TTS_IAM_TOKEN` или `YANDEX_STT_IAM_TOKEN`. API-ключ идёт в `..._API_KEY`; IAM-токен — другая, короткоживущая строка.

Официальные страницы: [Управление API-ключами](https://yandex.cloud/ru/docs/iam/operations/authentication/manage-api-keys) и [API-ключ: области действия](https://yandex.cloud/ru/docs/iam/concepts/authorization/api-key).

**Проверка:** у вас два секрета (или один, если используете только один плагин), они лежат в менеджере паролей, и область действия каждого совпадает с его плагином.

### 2.6 Вместо API-ключа — IAM-токен

IAM-токен — короткоживущий bearer-токен. Плагины его поддерживают, но для настольной установки API-ключ проще.

Получить токен через Yandex Cloud CLI:

```powershell
yc iam create-token
```

Вывод — токен (начинается с `t1.`). Требования:

- CLI должен быть установлен и авторизован ([быстрый старт CLI](https://yandex.cloud/ru/docs/cli/quickstart));
- для токена **сервисного аккаунта** профиль CLI должен быть настроен на авторизованный ключ этого аккаунта; файл авторизованного ключа — не то же самое, что API-ключ, и его нельзя вставлять в плагин;
- токен живёт **не больше 12 часов**, и Яндекс рекомендует обновлять его чаще, например каждый час;
- в режиме IAM нужно также передать идентификатор каталога: `YANDEX_TTS_FOLDER_ID` / `YANDEX_STT_FOLDER_ID` либо `folderId` в `plugin-config.json`.

Когда IAM-токен уместен:

- короткая отладочная сессия, когда не хочется создавать ключ;
- автоматизация, которая сама получает свежий токен (сервис метаданных, обмен JWT, обновление секрета в CI) и успевает заменить его до истечения;
- машина, где менеджер секретов подставляет короткоживущий токен при старте процесса.

Когда он плохо подходит:

- настольный компьютер, где `dsh web` работает днями: токен истечёт, и TTS/STT начнут возвращать `401` посреди дня;
- установка, где никто не будет помнить про обновление.

**Важно:** если заданы и IAM-токен, и API-ключ, **побеждает IAM-токен**. Просроченный токен тогда даст `401`, хотя в том же файле лежит вполне рабочий API-ключ. Если возвращаетесь к API-ключу, очистите поля IAM, а не оставляйте просроченный токен рядом с ключом.

Официальные страницы: [Получение IAM-токена для аккаунта на Яндексе](https://yandex.cloud/ru/docs/iam/operations/iam-token/create) и [Получение IAM-токена для сервисного аккаунта](https://yandex.cloud/ru/docs/iam/operations/iam-token/create-for-sa).

### 2.7 Чек-лист перед тем, как трогать DSH

- [ ] платёжный аккаунт активен;
- [ ] каталог создан, его идентификатор известен;
- [ ] сервисный аккаунт `dsh-speechkit` создан;
- [ ] в правах каталога есть `ai.speechkit-tts.user` и/или `ai.speechkit-stt.user`;
- [ ] создан один API-ключ на плагин, у каждого — своя область действия;
- [ ] секреты сохранены в надёжном месте и их нет в репозитории;
- [ ] плагин(ы) установлены (см. [инструкцию по установке](install.ru.md)):
  ```powershell
  dsh plugin --profile web add "https://github.com/Feskel2/dsh-extras/releases/download/v1.1.0/dsh-voice-reply.tgz"
  dsh plugin --profile web add "https://github.com/Feskel2/dsh-extras/releases/download/v1.1.0/dsh-speech-to-text-yandex.tgz"
  ```

## 3. Доставляем секрет плагину

### 3.1 Как плагины читают доступы

Оба плагина определяют доступы на каждый запрос. Точный приоритет различается, и это важно, когда вы что-то поменяли, а ничего не изменилось:

| Плагин | Порядок (побеждает первое непустое значение) |
|---|---|
| `dsh-voice-reply` | **переменные окружения → `plugin-config.json`** |
| `dsh-speech-to-text-yandex` | **config в `cordis.patch.yml` → переменные окружения → `plugin-config.json` → значения по умолчанию** |

Общие правила в обоих:

- **IAM-токен приоритетнее API-ключа.** Если любое поле IAM-токена непустое, плагин авторизуется через `Bearer` и ждёт идентификатор каталога; иначе используется `Api-Key`. Приоритет применяется **по полям**, а режим авторизации выбирается после этого: просроченный IAM-токен, оставшийся в источнике с более низким приоритетом, всё равно перекроет свежий API-ключ из источника с более высоким. Очищайте поля IAM, когда переходите на ключ.
- **Пустые значения пропускаются.** Пустая строка (или пробелы) в источнике с более высоким приоритетом не считается «намеренно пустым значением», а просто пропускается.
- **`plugin-config.json` перечитывается на каждый запрос.** Замена ключа там применяется со следующим синтезом или распознаванием, без перезапуска `dsh web`.
- **Переменные окружения фиксируются при старте `dsh web`.** Чтобы их изменить, процесс нужно перезапустить.
- Имена переменных у плагинов разные (`YANDEX_TTS_*` и `YANDEX_STT_*`), а вот legacy-имена совпадают. Не используйте legacy-имена, чтобы выдать двум плагинам разные ключи, — они прочитают одно и то же значение.

Переменные окружения:

| Назначение | TTS (`dsh-voice-reply`) | STT (`dsh-speech-to-text-yandex`) |
|---|---|---|
| API-ключ | `YANDEX_TTS_API_KEY` | `YANDEX_STT_API_KEY` |
| IAM-токен | `YANDEX_TTS_IAM_TOKEN` | `YANDEX_STT_IAM_TOKEN` |
| Идентификатор каталога (только IAM) | `YANDEX_TTS_FOLDER_ID` | `YANDEX_STT_FOLDER_ID` |
| Legacy-синонимы | `YANDEX_SPEECHKIT_API_KEY`, `YANDEX_SPEECHKIT_IAM_TOKEN`, `YANDEX_SPEECHKIT_FOLDER_ID` | те же три имени |
| Короткие алиасы | `YC_API_KEY`, `YC_IAM_TOKEN`, `YC_FOLDER_ID` | те же три имени |

Плагин срезает вставленный префикс авторизации (`Api-Key `, `Bearer `, `apikey `), поэтому скопировать заголовок целиком не страшно. Но всё же вставляйте только сам секрет.

Необязательное упрощение: DSH загружает `.env` из каталога, из которого запущен, и из `$DSH_HOME\.env` в окружение процесса при старте. Значения, уже присутствующие в реальном окружении, побеждают. Это работает как переменные окружения — читается при старте и требует перезапуска, — но секрет не попадает ни в профиль PowerShell, ни в `node_modules`.

### 3.2 Способ A — переменные окружения

Используйте его, если не хотите держать секрет внутри каталога плагина или если один и тот же ключ должен получать не один процесс.

Временно, только для текущего окна PowerShell:

```powershell
$env:YANDEX_TTS_API_KEY = '<tts-api-key>'
$env:YANDEX_STT_API_KEY = '<stt-api-key>'
dsh web
```

Постоянно, для текущего пользователя Windows (только новые процессы):

```powershell
[Environment]::SetEnvironmentVariable('YANDEX_TTS_API_KEY', '<tts-api-key>', 'User')
[Environment]::SetEnvironmentVariable('YANDEX_STT_API_KEY', '<stt-api-key>', 'User')
```

Классическая альтернатива:

```powershell
setx YANDEX_TTS_API_KEY "<tts-api-key>"
setx YANDEX_STT_API_KEY "<stt-api-key>"
```

Обе формы пишут в пользовательское окружение. `setx` не обновляет текущее окно и тоже действует только на процессы, запущенные после него.

Если используете IAM-токен, задавайте токен и идентификатор каталога:

```powershell
[Environment]::SetEnvironmentVariable('YANDEX_TTS_IAM_TOKEN', '<iam-token>', 'User')
[Environment]::SetEnvironmentVariable('YANDEX_TTS_FOLDER_ID', '<folder-id>', 'User')
```

Затем **перезапустите `dsh web` из того же окружения**:

1. Остановите работающий процесс `dsh web` (Ctrl+C в его окне или закройте окно, из которого он запущен).
2. Закройте терминал, в котором задавали переменные, и откройте новый — уже открытый терминал не увидит новое пользовательское окружение.
3. Запустите `dsh web` снова и откройте напечатанный адрес.

Если `dsh web` запускается из ярлыка на рабочем столе, из планировщика задач или из папки автозагрузки, ярлык запускает Проводник. После установки пользовательской переменной выйдите из системы и войдите снова (или перезапустите Проводник), чтобы новый процесс её унаследовал. Перезапуска только сессии DSH или перезагрузки страницы недостаточно: **переменные окружения читаются один раз, при старте процесса хоста.**

Проверить, что переменная видна, не печатая секрет:

```powershell
if ([Environment]::GetEnvironmentVariable('YANDEX_TTS_API_KEY', 'User')) { 'set' } else { 'missing' }
```

Почему порядок важен: `plugin-config.json` читается на каждый запрос, а окружение — это снимок процесса. Если вы поменяли переменную, а плагин ведёт себя по-старому, значит хост не был перезапущен из окружения с новым значением.

### 3.3 Способ B — `plugin-config.json` рядом с плагином

Самый простой вариант для одного пользователя на настольном компьютере: один файл на плагин, перезапуск не нужен, общесистемного состояния нет.

После обычной установки `dsh plugin --profile web add` пакеты лежат в профиле `web`:

| Плагин | Файл |
|---|---|
| `dsh-voice-reply` | `%USERPROFILE%\.dsh\profiles\web\node_modules\dsh-voice-reply\plugin-config.json` |
| `dsh-speech-to-text-yandex` | `%USERPROFILE%\.dsh\profiles\web\node_modules\dsh-speech-to-text-yandex\plugin-config.json` |

Если задан `DSH_HOME`, замените `%USERPROFILE%\.dsh` на его значение:

```powershell
$dshHome = if ($env:DSH_HOME) { $env:DSH_HOME } else { Join-Path $env:USERPROFILE '.dsh' }
$ttsDir = Join-Path $dshHome 'profiles\web\node_modules\dsh-voice-reply'
$sttDir = Join-Path $dshHome 'profiles\web\node_modules\dsh-speech-to-text-yandex'
```

Создайте файлы из поставляемых примеров:

```powershell
Copy-Item (Join-Path $ttsDir 'plugin-config.example.json') (Join-Path $ttsDir 'plugin-config.json')
Copy-Item (Join-Path $sttDir 'plugin-config.example.json') (Join-Path $sttDir 'plugin-config.json')
notepad (Join-Path $ttsDir 'plugin-config.json')
notepad (Join-Path $sttDir 'plugin-config.json')
```

Если файл уже существует, редактируйте его, а не перезаписывайте — в нём может уже лежать ваш ключ и ваши настройки.

Минимальный файл для TTS (пропущенные поля берутся по умолчанию):

```json
{
  "apiKey": "<tts-api-key>"
}
```

Минимальный файл для STT:

```json
{
  "apiKey": "<stt-api-key>"
}
```

Если копируете полный пример, оставьте настройки и заполните только доступы. Для TTS:

```json
{
  "apiKey": "<tts-api-key>",
  "iamToken": "",
  "folderId": "",
  "endpoint": "https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize",
  "voice": "marina",
  "lang": "ru-RU",
  "format": "mp3",
  "speed": 1.32,
  "summaryMaxChars": 500,
  "debug": false,
  "logFile": ".state/events.log",
  "autoSpeak": true
}
```

Для STT пример выглядит так:

```json
{
  "apiKey": "<stt-api-key>",
  "folderId": "",
  "iamToken": "",
  "endpoint": "https://stt.api.cloud.yandex.net/speech/v1/stt:recognize",
  "topic": "general",
  "profanityFilter": false,
  "rawResults": false,
  "chunkSeconds": 25,
  "searchBackSeconds": 3,
  "requestTimeoutMs": 45000,
  "maxAttempts": 3,
  "debug": true,
  "logFile": ".state/events.log"
}
```

Заметки, которые экономят время:

- **Перезапуск не нужен.** Файл перечитывается на каждый запрос; следующий ответ или следующая запись используют новый ключ.
- **Страница настроек плагина пишет в этот же файл.** `dsh-voice-reply` хранит там свои настройки интерфейса (`autoSpeak`, `summaryMaxChars`, а также голос и скорость в сборках, где их можно менять); запись сохраняет поля с доступами. Поэтому файл может измениться после нажатия «Сохранить» в интерфейсе — это нормально.
- **В репозитории только пример.** Репозиторий поставляет `plugin-config.example.json` с пустыми полями; `plugin-config.json` в `.gitignore`. При обычной установке файл лежит в `node_modules` профиля, так что в репозиторий он и так не попадает.
- **Обновление плагина может заменить каталог пакета.** Держите копию ключа в менеджере паролей, а не только в этом файле.
- **JSON строгий.** Никаких комментариев, висячих запятых и BOM. В Windows редактор, сохраняющий «UTF-8 with BOM», приводит к ошибке «некорректный JSON». В VS Code в статус-баре должно быть `UTF-8`, а не `UTF-8 with BOM`.
- Проверьте файл ровно так, как его прочитает Node:

  ```powershell
  node -e "JSON.parse(require('fs').readFileSync(process.argv[1], 'utf8')); console.log('ok')" (Join-Path $ttsDir 'plugin-config.json')
  ```

### 3.4 Способ C — строка плагина в `cordis.patch.yml` профиля

Собственный слой патча профиля — это `%USERPROFILE%\.dsh\profiles\web\cordis.patch.yml` (или `$DSH_HOME\profiles\web\cordis.patch.yml`). Он предназначен для настроек поведения, а не для секретов:

```yaml
- id: voice-reply
  config:
    voice: marina
    summaryMaxChars: 500

- id: speech-to-text-yandex
  config:
    chunkSeconds: 20
```

**Не кладите сюда API-ключи и IAM-токены.** Этот файл — часть конфигурации профиля: его легко скопировать на другую машину, приложить к отчёту об ошибке или синхронизировать в репозиторий dotfiles. Оба README плагинов и `SECURITY.md` описывают доступы как переменные окружения или локальный `plugin-config.json`, но не как config профиля. Для `dsh-voice-reply` блок `config` вообще не может передать доступы — код читает ключ только из окружения и `plugin-config.json`. Для `dsh-speech-to-text-yandex` config в патче имеет **высший** приоритет и молча перекрыл бы окружение и файл — ещё одна причина не держать там доступы.

### 3.5 Что выбрать

| Ситуация | Рекомендация |
|---|---|
| Один человек, один настольный Windows | **`plugin-config.json`** — без перезапуска, легко менять и удалять |
| Ключ не должен лежать внутри `node_modules` | **Пользовательские переменные окружения** — один перезапуск `dsh web` после каждого изменения |
| Несколько процессов `dsh web` или сервисный аккаунт для автоматизации | Переменные окружения либо `.env`, читаемый при старте; убедитесь, что каждый процесс получает нужный ключ |
| Сервер или CI с менеджером секретов | Окружение, подставляемое при старте процесса, либо короткоживущий IAM-токен с автообновлением |
| Хочется положить ключ в `cordis.patch.yml` | Не надо — используйте один из двух способов выше |

## 4. Проверяем, что заработало

### 4.1 Перезапуск и открытие DSH

После установки плагина перезапустите `dsh web` (bundle-слои монтируются при старте) и откройте напечатанный адрес. Если меняли только `plugin-config.json`, перезапуск не нужен. Если сомневаетесь — перезапустите один раз: это снимает вопрос «дело в хосте или в файле?».

### 4.2 TTS (`dsh-voice-reply`)

1. Откройте **Settings → General** (**«Настройки» → «Общие»**). Найдите строку **«Озвучивать ответы голосом»** и включите её. Это настройка `autoSpeak`.
2. Откройте **«Плагины» → «Голосовые ответы» → «Настроить»**. Страница показывает лимит символов озвучки, `autoSpeak`, голос и скорость. Задайте лимит; 500 символов — примерно 30 секунд речи.
3. Если в вашей сборке на этой странице есть кнопка **«Прослушать»**, нажмите её. Это самая быстрая проверка без чата: хост синтезирует короткий пример текущим голосом и с текущей скоростью. В старых сборках такой кнопки может не быть — переходите к следующему шагу.
4. Без кнопки прослушивания: задайте простой вопрос и дождитесь завершения ответа. Плагин озвучивает только ответы, завершённые **после** его установки, историю он не перечитывает. Либо нажмите **🔊** у любого готового ответа — повтор работает и для старых ответов.
5. Ожидаемый результат: над полем ввода появляется чип с подготовкой/чтением краткого содержания, звук играет, а повторное нажатие 🔊 проигрывает его из кэша на диске без нового обращения к Яндексу.

Если чип говорит **«Озвучивание не настроено…»** (`Text-to-speech is not configured`), хост не видит ни переменную окружения, ни поле в файле. Вернитесь к [разделу 3](#3-доставляем-секрет-плагину) и проверьте путь и имя поля.

### 4.3 STT (`dsh-speech-to-text-yandex`)

1. Убедитесь, что включён штатный bundle **Voice input**: **«Плагины» → «Голосовой ввод»**. Плагин Яндекса только регистрирует провайдер распознавания; интерфейс микрофона принадлежит этому bundle.
2. Откройте настройки Voice input. Установите **«Служба распознавания»** = **Yandex SpeechKit**, язык распознавания — `ru` или `en`.
3. Статус должен показать **«Облачное распознавание речи готово»**. Этому провайдеру не нужно скачивать модель, поэтому он готов сразу.
4. Нажмите на микрофон, при запросе разрешите доступ к микрофону в браузере, произнесите фразу и остановите запись. Распознанный текст должен появиться в черновике сообщения.
5. Если провайдера нет в списке или выбрана другая служба, выберите Yandex SpeechKit явно и перезагрузите страницу. Патч плагина выбирает его по умолчанию, но настройка уровня профиля может это перекрыть.

### 4.4 Журналы

Оба плагина пишут диагностику в `.state/events.log` **внутри каталога своего пакета**:

```powershell
$dshHome = if ($env:DSH_HOME) { $env:DSH_HOME } else { Join-Path $env:USERPROFILE '.dsh' }
$profile = Join-Path $dshHome 'profiles\web\node_modules'

Get-Content (Join-Path $profile 'dsh-voice-reply\.state\events.log') -Tail 20
Get-Content (Join-Path $profile 'dsh-speech-to-text-yandex\.state\events.log') -Tail 20
```

Журнал — это JSON Lines: один объект на запрос. В нём счётчики, тайминги, HTTP-статусы и коды ошибок — **без текста ответов, без аудио, без ключей**.

Что искать:

| Плагин | Событие | Смысл |
|---|---|---|
| TTS | `activate` | Хост загрузил плагин |
| TTS | `speak.ok` | Синтез удался; есть число символов и тайминг |
| TTS | `preview.ok` | Пример со страницы настроек удался |
| TTS | `speak.error`, `preview.error` | Ошибка; поля `status` и `code` показывают, это 401, 403, 429 и т. д. |
| TTS | `preferences.ok` | Страница настроек сохранила предпочтение |
| STT | `activate` | Хост загрузил плагин |
| STT | `provider.registered` | `yandex-speechkit` появился в Voice input |
| STT | `transcribe.ok` | Распознавание удалось; есть длительность аудио и число кусков |
| STT | `transcribe.error` | Ошибка; есть HTTP-статус и сообщение |

Если журнал STT пустой, проверьте, не скопирован ли пример с `"debug": false`, или поставьте `"debug": true`. Плагин TTS пишет журнал независимо от значения `debug`. Если файла нет вообще, путь неверен — проверьте, что пакет лежит в `profiles\web\node_modules` и не переопределён ли `DSH_HOME`.

В `dsh-voice-reply` путь журнала фиксирован — `.state/events.log`; поле `logFile` из примера его не меняет. В `dsh-speech-to-text-yandex` поле `logFile` учитывается.

### 4.5 Проверки первого запуска

- Хост перезапущен после `dsh plugin add`.
- Страница перезагружена после перезапуска.
- В списке плагинов включён нужный плагин.
- Для TTS ответ завершился после установки плагина (или вы нажали 🔊).
- Для TTS вкладка была в фокусе; в скрытой вкладке автозапуск намеренно откладывается.
- Для STT включён bundle Voice input и разрешён микрофон.

## 5. Если не работает

### 5.1 TTS

| Что видно | Вероятная причина | Что делать |
|---|---|---|
| Чип **«Озвучивание не настроено…»**; статус отдаёт `configured: false` | Ключа нет ни в одном источнике; опечатка в имени переменной; неверный путь к файлу; пустое поле `apiKey` | Положите ключ в `YANDEX_TTS_API_KEY` (и перезапустите `dsh web`) или в `plugin-config.json` рядом с `index.js`. В тексте ошибки плагин указывает на `plugin-config.json` как на файл, который нужно заполнить |
| `401 UNAUTHORIZED` / «Yandex SpeechKit отклонил ключ» | Для TTS использован STT-ключ; у ключа только `yc.ai.speechkitStt.execute`; ключ отозван или истёк; просроченный IAM-токен перекрывает рабочий API-ключ | Создайте/перевыпустите ключ с `yc.ai.speechkitTts.execute`; очистите просроченные поля IAM; проверьте область действия и дату последнего использования ключа в консоли |
| `403 PERMISSION_DENIED` / «Yandex SpeechKit запретил доступ» | `ai.speechkit-tts.user` не выдана на каталог; ключ принадлежит сервисному аккаунту из другого каталога; роль выдали секунды назад | Выдайте роль на каталог, которому принадлежит сервисный аккаунт; подождите несколько минут; повторите |
| `429` / «превышена квота» | Квота или лимит частоты SpeechKit; всплеск ответов | Плагин сам повторяет 429/5xx. Если повторяется — смотрите [квоты](https://yandex.cloud/ru/docs/speechkit/concepts/limits), подождите или сократите озвучку |
| `400` / «отклонил запрос» | Неверные параметры (сочетание голоса/формата/эмоции, пустой текст) | Начните с голоса и формата по умолчанию; отключите эмоцию; посмотрите текст ошибки в чипе |
| Звука нет, но чип говорит, что играет | Вкладка без звука, не то устройство вывода, громкость, Bluetooth | Проверьте mute вкладки и устройство вывода ОС; кнопка остановки — в чипе |
| Первое автопроигрывание заблокировано | Политика autoplay браузера | Кликните в любом месте страницы и нажмите 🔊. Это правило браузера, а не ошибка плагина |
| Ответ не озвучивается автоматически | Выключен `autoSpeak`; вкладка была скрыта; ответ завершился до установки плагина | Включите Settings → General («Настройки» → «Общие») → «Озвучивать ответы голосом»; верните фокус во вкладку; для старых ответов нажмите 🔊 |
| Плагин сообщает о некорректном JSON | Комментарии, висячая запятая или BOM в `plugin-config.json` | Проверьте командой `node -e` из раздела 3.3; пересохраните файл как UTF-8 без BOM |
| После правки переменной окружения ничего не меняется | Хост не перезапущен или перезапущен из старого терминала | Остановите `dsh web`, откройте новый терминал, запустите снова; если запуск из ярлыка — выйдите и войдите в систему |
| Всё работало, через время появился `401` | Истёк IAM-токен (живёт не больше 12 часов) | Замените токен или перейдите на API-ключ и очистите поля IAM |

### 5.2 STT

| Что видно | Вероятная причина | Что делать |
|---|---|---|
| При записи «Yandex SpeechKit не настроен» | Нет `apiKey`/`iamToken` в файле или окружении | Заполните `plugin-config.json` рядом с `index.mjs` или задайте `YANDEX_STT_API_KEY`; перезапуск нужен только для окружения |
| `401 UNAUTHENTICATED` | Для STT использован TTS-ключ; у ключа нет `yc.ai.speechkitStt.execute`; сервисный аккаунт удалён; побеждает просроченный IAM-токен | Создайте ключ с областью STT; проверьте сервисный аккаунт; очистите просроченные поля IAM |
| `403 PERMISSION_DENIED` | Нет `ai.speechkit-stt.user` на каталоге; неверный `folderId` в режиме IAM | Выдайте роль на правильный каталог; проверьте `YANDEX_STT_FOLDER_ID` / `folderId`; подождите несколько минут |
| `429 RESOURCE_EXHAUSTED` | Квота или лимит частоты | Плагин повторяет с паузой; если не проходит — проверьте квоты или диктуйте короче |
| `400 INVALID_ARGUMENT` | Аудио отклонено (неверный формат/частота или пустая запись) | Используйте обычный сценарий Voice input, разрешите микрофон, перезагрузите страницу; посмотрите detail в журнале |
| В службе распознавания нет Yandex SpeechKit | Плагин не установлен/не смонтирован или выключен bundle Voice input | Переустановите `dsh-speech-to-text-yandex`, перезапустите `dsh web`, включите «Плагины» → «Голосовой ввод» |
| Провайдер не выбран (или используется локальное распознавание) | В Voice input выбрана другая служба либо запись провайдера отсутствует | Выберите **Yandex SpeechKit** явно и перезагрузите страницу |
| В длинной записи теряется слово на стыке | Записи длиннее 28 секунд режутся; разрез ставится в самое тихое окно 100 мс, но слово может обрезаться | Диктуйте кусками по 20–25 секунд; это ограничение SpeechKit REST v1, а не настройка плагина |
| В расшифровке нет знаков препинания | SpeechKit REST v1 возвращает чистый текст | Так работает сервис; пунктуацию и тайминги он не добавляет |
| Микрофон недоступен | Нет разрешения браузера или не выбрано устройство ввода | Разрешите микрофон для страницы DSH; выберите другое устройство ввода в Voice input |
| Журнал STT пустой | `debug` равен `false` (пример файла ставит false) или неверный путь | Поставьте `"debug": true` в `plugin-config.json`; проверьте путь к журналу |

### 5.3 Пояснения к самым запутанным ошибкам

- **401 и 403 — разное.** `401` означает, что сам доступ не принят: не тот тип ключа, нет области действия, ключ отозван/истёк, просрочен IAM-токен. `403` означает, что доступ распознан, но у сервисного аккаунта нет роли на каталоге. Исправление одного не исправляет другое.
- **Область действия — это не роль.** Область ограничивает, что можно вызывать конкретным API-ключом; роль даёт сервисному аккаунту право пользоваться сервисом. Нужны обе: ключ с правильной областью, но без роли получит `403`; ключ с ролью, но не той областью будет отклонён — обычно с `401`, иногда с `403`; в любом случае проверьте область действия.
- **Распространение прав.** Сразу после выдачи роли вызовы могут ещё возвращать `403`. Подождите несколько минут и повторите, прежде чем пересоздавать ключи.
- **Ключ показывается один раз.** Если секрет не найден, восстановить его нельзя. Удалите ключ и создайте новый; не пытайтесь «достать» его из консоли.

## 6. Ротация и безопасность

### 6.1 Ротация API-ключа

1. В консоли откройте **Identity and Access Management → Сервисные аккаунты → dsh-speechkit → API-ключи**.
2. Создайте новый ключ с той же областью действия и новым описанием (например, `dsh-voice-reply TTS 2026-11`).
3. Положите новый секрет туда же, откуда брался старый: в `plugin-config.json` (без перезапуска) или в переменную окружения (с перезапуском `dsh web`).
4. Запустите синтез или распознавание и проверьте в журнале `speak.ok` / `transcribe.ok`.
5. Удалите старый ключ: меню строки → **Удалить**, либо
   ```powershell
   yc iam api-key delete <old-key-id>
   ```
6. Запишите дату ротации. Если у ключа задан срок действия, поставьте дату в календарь.

### 6.2 Ротация IAM-токена

Просто получите новый через `yc iam create-token` и замените значение. В `plugin-config.json` изменение применяется сразу; в переменной окружения нужен перезапуск. Не держите просроченный токен рядом с рабочим API-ключом — токен побеждает.

### 6.3 Правила

- **Никогда не коммитьте ключ.** В репозитории есть только `plugin-config.example.json` с пустыми полями; `plugin-config.json` в `.gitignore`.
- **Никогда не вставляйте ключ в чат, issue, скриншот или отчёт об ошибке.** Консоль показывает только замаскированное значение после создания не просто так.
- **Разные ключи для TTS и STT.** Разные области действия; утечка затрагивает один сервис, а отзыв одного не ломает другой.
- **Минимальные права.** Одна область действия на ключ; роль `ai.speechkit-*` на каталог, а не на всё облако, если нет причины делать шире.
- **Ставьте срок действия**, если консоль его предлагает, и меняйте ключи по расписанию.
- **Держите файл приватным.** `plugin-config.json` лежит в вашем профиле пользователя; не копируйте его в проект под контролем версий.
- **Смотрите `last_used_at`.** Страница сервисного аккаунта показывает, когда ключ использовался последний раз; неожиданное недавнее использование — повод отозвать его.
- **Если ключ утёк:** сначала отзовите его, затем создайте замену и обновите плагин. Именно отзыв останавливает утечку; обновление плагина может подождать.

Что плагины делают с секретом:

- он остаётся в процессе хоста `dsh web`;
- он отправляется только на настроенный endpoint SpeechKit по HTTPS;
- он никогда не передаётся в браузер, не пишется в `.state/events.log` и не включается в npm-пакет;
- в пакете поставляется только пример файла с пустыми полями.

## 7. Стоимость

SpeechKit — платный сервис. Точная сумма зависит от действующих тарифов Yandex Cloud, версии API и режима:

- **TTS** тарифицируется за синтез; плагины используют TTS API v1 и краткое содержание (по умолчанию 500 символов), а не весь ответ;
- **STT** тарифицируется за длительность распознанного аудио; плагин отправляет запись кусками (цель — 25 секунд, максимум — 28 секунд), и каждый кусок — отдельный запрос;
- **Кэш в `dsh-voice-reply`** означает, что повторное прослушивание того же ответа с тем же голосом/скоростью/форматом не обращается к Яндексу заново. Кэш лежит во временной папке ОС (`%TEMP%\dsh-voice-reply-cache` в Windows), хранит записи 7 дней и ограничен 512 МБ. У STT кэша нет: каждая запись отправляется и тарифицируется.

Не ориентируйтесь на цены из блогов и на этот документ — тарифы и единицы тарификации меняются. Смотрите актуальные цифры и условия бесплатного уровня/грантов вашего аккаунта на официальной странице тарифов:

- [Правила тарификации SpeechKit](https://yandex.cloud/ru/docs/speechkit/pricing)
- [Квоты и лимиты SpeechKit](https://yandex.cloud/ru/docs/speechkit/concepts/limits)

Практический контроль расходов:

- держите лимит озвучки на 500 символах, если вам действительно не нужно больше;
- используйте один и тот же голос/скорость/формат, чтобы повторы попадали в кэш;
- диктуйте короткими кусками; длинная запись превращается в несколько STT-запросов;
- после первого дня использования загляните в раздел **Биллинг** консоли.

## Приложение: шпаргалка CLI

```powershell
# Каталог
yc resource-manager folder create --name dsh-speechkit
yc resource-manager folder list

# Сервисный аккаунт
yc iam service-account create --name dsh-speechkit
yc iam service-account get dsh-speechkit

# Роли (подставьте id каталога и id сервисного аккаунта из вывода выше)
yc resource-manager folder add-access-binding <folder-id> `
  --role ai.speechkit-tts.user `
  --service-account-id <service-account-id>

yc resource-manager folder add-access-binding <folder-id> `
  --role ai.speechkit-stt.user `
  --service-account-id <service-account-id>

# Два ключа с областями действия — сразу сохраните поле secret:
yc iam api-key create --service-account-name dsh-speechkit `
  --description "dsh-voice-reply TTS" `
  --scopes yc.ai.speechkitTts.execute

yc iam api-key create --service-account-name dsh-speechkit `
  --description "dsh-speech-to-text STT" `
  --scopes yc.ai.speechkitStt.execute

# Короткоживущая альтернатива в режиме IAM (нужен ещё folder id)
yc iam create-token
```
